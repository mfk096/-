## Сделано

- Раздел «Места установки» (`/locations`): дерево произвольной глубины, раскрытие и сворачивание, поиск по названию, счётчик единиц в узле вместе с вложенными. Крупные зоны нажатия, чтобы работать с телефона.
- Создание, переименование, смена типа и перенос узла к другому родителю или в корень. Цикл возвращает понятную ошибку. Удаления нет: узел архивируют. Если в нём есть дети или единицы, база отказывает и пишет, что сначала перенести.
- Ответственный выбирается из справочника сотрудников. Если своё значение пустое, карточка и дерево показывают унаследованного с пометкой «унаследован от …».
- Вкладка «Сотрудники»: список, создание и правка ФИО, должности, телефона и необязательной привязки к пользователю приложения. Если на сотрудника есть ссылки, удаление запрещено — карточку архивируют.
- Страница узла (`/locations/:id`): хлебные крошки полного пути, ответственный, список единиц в узле и ниже со ссылкой в карточку.
- В форме новой единицы и в перемещении на карточке плоский список мест заменён выбором из дерева с поиском по пути. В списке единиц и на карточке видны полный путь и ответственный.
- Кнопки правки справочников видны только роли `admin`, как в RLS. Редактор по-прежнему выбирает место у единицы.

## Проверено

`./supabase/tests/run.sh` на локальном Postgres 16, весь прогон зелёный, включая прежние правила, RLS, сид и закрытие функций:

- наследование ответственного и источник («унаследован от» узла-предка), свой ответственный перекрывает предка;
- `equipment_count` считает единицы узла и всех потомков, `direct_equipment_count` — только сам узел;
- архив места с единицами или детьми отвергается с текстом про перенос; пустой узел архивируется;
- `move_location` переносит узел, отвергает цикл, перенос в себя и архивного родителя;
- сотрудника со ссылкой удалить нельзя, архивировать можно; архивного нельзя назначить заново; без ссылок удаление проходит;
- `authenticated` вызывает `move_location` и `location_responsible_source`, admin под RLS переносит узел, editor получает «Недостаточно прав для изменения мест», anon не вызывает RPC и не читает `employees_directory`;
- новые функции не `security definer`; повтор миграции снимает случайный `EXECUTE` у `anon` и `PUBLIC` и оставляет его у `authenticated`;
- сид: участок печати наследует Ивана от завода, счётчики поддерева сходятся с четырьмя демо-единицами, у `KYOC-001` в `equipment_list` тот же унаследованный ответственный.

`npm run lint`, `npm run typecheck` и `npm run build` во `frontend/`.

Без ключей Supabase переход на `/locations` открывает русскую страницу входа и подсказку, что заполнить `VITE_SUPABASE_URL` и anon key. Само дерево, формы и кнопки по ролям в браузере не прокликивались: локального API Supabase нет, а на боевой проект миграцию и тестовые записи этот этап не отправляет.

## Спорные моменты

- Тип узла (`kind`) в базе по-прежнему свободный текст, как в решении 4. В интерфейсе это список: завод, цех, участок, помещение, склад, линия, рабочее место. Незнакомое значение из базы в списке сохраняется.
- Архив запрещён при любом ребёнке, в том числе уже архивном, и при любой единице, которая сейчас стоит в узле, включая «Списано». Старые строки `movements` не мешают.
- Внутрь архивного узла нельзя ни создать место, ни перенести существующее.
- Архив сотрудника не снимает его с мест, где он уже указан: эффективный ответственный остаётся прежним, пока его не сменят. Новое назначение архивного человека отвергается.
- Счётчик в дереве — текущие единицы поддерева, не число исторических посещений.
- `move_location` работает с правами вызывающего и дополнительно проверяет роль `admin`. Это не `security definer`.
