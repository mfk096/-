# Архитектура

Журнал решений: [decisions.md](decisions.md). Черновик таблиц: [data-model.md](data-model.md).

## Сейчас (этап 1)

- SPA в `frontend/`: Vite, React 18, TypeScript 5.9 (`strict`), Tailwind CSS, shadcn/ui, React Router, TanStack Query.
- Вход через Supabase Auth: email и пароль. Формы регистрации нет. Сброс пароля — письмо со ссылкой на `/reset-password`.
- Клиент создаётся в `frontend/src/lib/supabase.ts` только из `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Ключ `service_role` во фронтенд не попадает.
- Если переменные не заданы или в них остались заглушки, страница входа показывает инструкцию. Приложение при старте не падает.
- Сессию держит `AuthProvider`. Разделы закрыты `ProtectedRoute`: без сессии браузер уходит на `/login`.
- На широком экране разделы в боковом меню. На телефоне — нижняя панель и шторка со всем списком. В шапке email или имя и выход.

С этапа 2 схема лежит в `supabase/migrations/`: таблицы учёта, выдача кодов, история, поверки, RLS. Фронтенд читает её типизированным клиентом и показывает номенклатуру, единицы, дерево мест с ответственными, журнал, график поверок, QR-этикетки и сканер. Импорт Excel идёт одним RPC на файл. Свидетельства поверок лежат в приватном бакете Storage. Логика учёта остаётся в SQL и в React, без облачных сервисов Supabase помимо Postgres, Auth, RLS и Storage.

Адрес и anon key по умолчанию берутся из `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Экран «Настройки подключения» может заменить их локально, без пересборки. QR ведёт на публичный адрес карточки (`VITE_PUBLIC_APP_URL`, по умолчанию GitHub Pages). Старый код после смены префикса всё ещё открывает единицу и просит заменить этикетку. Android-оболочка Capacitor разрешает cleartext HTTP к локальному серверу.

Реальные данные завода в облако не кладут. Облачный проект — для разработки на тестовых данных. После проверки на тестовом хостинге переезд на self-hosted Supabase на сервере завода делается только по отдельному распоряжению владельца.
